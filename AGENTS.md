## Política de deploy local e GitHub Actions (12/10/2026)

- Não usar GitHub Actions neste repositório para CI, deploy, agendamentos ou qualquer outra automação. Não criar, habilitar ou executar workflows em `.github/workflows`.
- Fazer deploy diretamente de um computador local autorizado para AWS, Cloudflare ou outro provedor do projeto, usando os scripts e as credenciais locais aprovadas.
- Antes de publicar, confirmar a conta, o ambiente e o destino, executar as validações locais adequadas e identificar a versão a implantar. Depois, verificar o resultado no provedor.
- Se faltar um procedimento local de deploy, implementá-lo e documentá-lo antes da próxima publicação. Não reativar GitHub Actions para contornar essa falta.
- Referências antigas a GitHub Actions em outros arquivos são legado e não anulam esta política.

# OpenCyber Academy reader guidance for AI agents

Start at the [home page](README.md). The [study path](STUDY_PATH.md) orders courses 001–207; then use the selected edition's current `SUBJECTS.md` rows from Lesson 01 to its last authored daily lesson, within weekly chapters where available, following **Next step** into the next course in the same language. The path's historic global ranges count legacy module positions, not weekday lessons. The [level index](levels/README.md) supports browsing, and the [AI guide](AI_GUIDE.md) explains the route. Each course links its planned language editions, one [course skill index](SKILLS.md), chapter index, book plan, authored manuscript when present, and [supplementary playbooks](playbooks/README.md).

- There is **one course skill per course**, in `levels/<level>/<area>/skill/SKILL.md`. Subjects are curriculum modules, with no separate skills. Plan one substantive book chapter per instructional week, with five distinct daily lessons inside it; see [the curriculum grid](CURRICULUM_GRID.md). These minimum baselines are not a cap on chapter count, lesson length, words or pages. Each daily lesson needs teaching, a worked example, an exercise with a worked answer and previous/index/next navigation. Existing subject-chapters are legacy content blocks until expanded, not completed weekly chapters or daily lessons. The rapid Incident Response English book now has [four weekly chapters and 20 daily lessons](levels/rapid-1-month/incident-response-resilience/en/SUBJECTS.md) within four modules.
- Use diagrams only when they explain a specific technical process, relationship or decision. Do not regenerate the removed `lesson-figures` blocks or generic lesson maps that connect section titles, examples and exercises; the course index and previous/next links already serve that purpose.
- Each course has one principal book per language. Read `book/PLAN.md` as an outline and `book/MANUSCRIPT.md` as authored text only where that file exists. A plan is never a finished book.
- At the end of every authored lesson and weekly chapter, and every `PLAN.md` summary, use its **Continue studying** block to go to the previous lesson or chapter, the course index, or the next lesson or chapter. If it links a plan, state clearly that teaching is not yet authored. Return to `SUBJECTS.md` after the final chapter to reach the next course.
- Keep a learner checkpoint with language, course number, chapter number, source state and exercises attempted. A planned next-step link is navigation, not proof of completion; stop at the first unwritten required lesson and identify any added explanation as supplementary.
- A completed book needs authored teaching for its course scope, a worked example and exercise with answer per daily lesson, and technical and editorial review. The weekly and daily counts are planning baselines without an upper cap; page count is a measurement, not the writing or completion target. Check the [book standard](BOOK_STANDARD.md) and [progress review](STRUCTURE_REVIEW.md) before claiming completion.
- The [area-by-language writing table](WRITING_PROGRESS.md) measures structural chapter-anchor coverage; the [course writing table](COURSE_WRITING_PROGRESS.md) retains the separate English-only legacy 300-word draft-depth test. The README introduces the project and leads learners to published lessons instead of displaying those percentages. Do not equate either measure with daily-lesson coverage, translation equivalence or completed books.
- The [course writing table](COURSE_WRITING_PROGRESS.md) adds chapter counts, manuscript words and hash-checked A4 measurements for all 207 individual English courses. A course with 100% draft coverage can still have an incomplete book.
- Active production order: write and review English source units first; translate a coherent reviewed and revision-pinned unit into Portuguese without waiting for unrelated English books; complete and review the Portuguese collection before beginning planned Spanish translation. Do not begin planned work in the other six languages until all three collections independently reach 100% of their full weekday curriculum and book review gates, with current translation parity and public site/MCP readback; see the [three-language gate](BOOK_STANDARD.md#sequential-production-order) and [translation workflow](TRANSLATION_WORKFLOW.md). Preserve existing later-language content and correct maintenance defects without counting those editions as active production. Other language folders may contain English working outlines pending translation; identify that state accurately.
- Cite the exact file and original factual sources. Label fictional cases, preserve third-party rights, and do not claim academic accreditation.
- Books lead the learning path; linked playbooks support practice.
- All teaching content, including unfinished chapter drafts, examples, labs, exercises, worked answers and course skills, belongs in this public repository. The private Engine contains only construction tools, measurements and operational records. A separate public draft is temporary and must be consolidated into the course's one `book/MANUSCRIPT.md`; do not count it as an additional book or lesson.

This public file guides readers and AI clients. Construction tools and operational procedures remain in a separate private editorial workspace.
